# 2026-10-18 · 功能与质量审计：Postgres 建表用的是 SQLite 语法，且缺三张核心表

- **来源会话**：@session:default/20261018_audit
- **类型**：踩坑排查 / 决策
- **涉及文件**：`db/pg.ts`、`db/mod.ts`、`routes/api.ts`、`routes/chat.ts`、`routes/models.ts`、`routes/premium.ts`、`services/catalog-sync.ts`、`main.ts`

## 问题

对全项目做一次功能+质量审计。目标是回答两件事：**代码能不能跑通、`deno check` 能不能过**
（新 CLI 把类型检查设成了部署闸门，见 2026-10-18 那篇笔记）。

审计前的已知症状：`deno check main.ts` 报 8 个类型错误；
线上 `/api/health`、`/api/health/detailed` 500（原因一直标注为"怀疑 Prisma 连接，未证实"）。

## 权衡

审计顺序上有两个选择：

| 方案 | 代价 |
|---|---|
| 只读代码静态推断 | 快，但"DDL 能不能建表"这类问题读不出来 —— 语法错误和执行期错误长得一样 |
| 用真实 Postgres 跑一遍（最终采用） | 需要 docker + 拉 `postgres:16-alpine`，约 3 分钟；但能一次性证伪所有"看起来对"的 SQL |

选了后者。做法：`sudo dockerd` 起容器，`DATABASE_URL` 指向它，用 `deno run --allow-sys main.ts`
真启动服务并逐条打端点。

## 结论

### 已证实的根因（不是猜测）

`db/pg.ts` 的 `initDb()` 用的是 **SQLite 建表语法**跑在 Postgres 上：

- `id INTEGER PRIMARY KEY AUTOINCREMENT` —— Postgres 无 `AUTOINCREMENT`
- `created_at TEXT DEFAULT (datetime('now'))` —— Postgres 无 `datetime()` 函数

更要命的是**缺三张真正被代码读写的表**：`api_keys`、`discovered_models`、`settings`。
`initDb()` 在第一条 `CREATE TABLE models` 就抛错 → `_ready` 变成 rejected promise →
之后每次 `await initDb()` 都立刻拒绝 → 所有走 Postgres 的端点 500。
这正是 `/api/health`、`/api/health/detailed`（裸调 `listApiKeys()`）500 的机制。
`/health/detailed` 里 `database: "connected"` 是硬编码，所以它还会说谎。

### 修正与验证结果（均为实证）

用真实 Postgres 16 验证，**fresh schema** 与**重复启动**都能幂等建表：

- 重写 `initDb()` 的 DDL 为标准 Postgres：`GENERATED BY DEFAULT AS IDENTITY`、`now()::text`、
  补齐 `api_keys` / `discovered_models` / `settings`，去重（原文件 `server_logs` 等重复 2–4 次），
  并按 FK 依赖排序（`attempt_key_label` 现在排在 `request_attempts` 之后）。
- 真实 Postgres 一次性建出 **40 张表、0 重复、0 未解析外键**。
- 首次真跑又抓到一个只有执行才知道的坑：`key_monthly_budget` 同时有
  `id ... IDENTITY PRIMARY KEY` 和 `PRIMARY KEY (key_id, month)` → `42P16 多个主键`。已删 `id` 列。
- DDL 改为**逐条** `sql.unsafe(stmt)`：Prisma 前面的 pooler 对多语句简单查询不友好，
  逐条还能精确报出是哪一条挂了。`onnotice: () => {}` 关掉每次冷启动 40 条
  "relation already exists, skipping" 噪音。

`deno check main.ts`：8 errors → **0**（11 个文件改动，全部 `deno check` 通过）。

端到端（连真实 PG）：`/api/health` 200、`/api/health/detailed` 200 且 `database: "connected"`
现在是 `pingDb()` 实测（`databaseDetail: db=openllm api_keys=9 models=0 settings=19`）、
`/api/keys` 200、`/api/settings/stats` `count:19`、启动日志 `seeded 9 api keys / 19 settings`。

### 一并修掉的功能/质量 bug（均实测）

1. `saveModels` 用了错误 API：`VALUES ${rowTuples}` 生成出 `$1` 语法错误。
   改为 postgres.js 文档写法 `sql(rows, ...columns)`。`POST /api/models` 从 500 → `{"ok":true,"saved":2}`。
2. `getModels`/`saveModels` 原来不落 `is_free` / `price_note` / `context_window`，
   导致 `/api/models/free` **永远返回 `[]`**。现已落库，`/api/models/free`、`/v1/models` 均能返回。
3. `/v1/models` 只读内存 catalog，现在合并 Postgres 里发现的模型。
4. `routes/chat.ts` 原来从**内存** `db.api_keys` 取 key，Dashboard 写 Postgres 的 key 在冷启动后不可见；
   改为经 `listApiKeys()` 读 Postgres（失败回退内存），并修 Hono 类型。解密路径实测成功。
5. `routes/premium.ts` 整文件是 Express 写法（`(req, res) => res.json()`），在 Hono 下必崩。
   改写为 Hono 并挂载到 `/api/premium`。
6. `routes/keys.ts`、`services/catalog-sync.ts` 引用了不存在的 `setSetting` / 未用的 `getDb`。
   清理导入；`catalog-sync` 的 `getSyncState` 补 `?? null` 类型收敛。
7. **静态文件路径穿越**：`DIST + filePath` 未过滤 `..`，可读越界文件。现按段拒绝 `..`/NUL，
   且仅 GET/HEAD 提供静态资源。
8. `/api/settings/set-password` 原来**无鉴权即可覆盖管理员密码**（接管漏洞）。
   现在：首次设置放行；已设置时必须带有效 session（兼容 `Bearer ` 前缀）。实测：无 token 改密 401。
9. `Deno.hostname()` 需要 `--allow-sys`，异常会让 `/health` 变裸 500。加 `safeHostname()` 兜底（返回 `unknown`）。

### 遗留风险（未解决，别当成已修）

1. **线上仍是旧 revision**：以上全是在本地/本地 PG 验证，**尚未重新部署**。线上 24 个缺端点、
   health 500 的状态要靠"逐条打端点"重新确认，不能靠部署工具的 `status`。
2. `deno lint` 仍有 **33 条 `require-await`**（Phase 0–7 的空壳 handler 留了 `async` 但无 `await`）。
   纯风格问题，不挡 `deno check`/部署，本次未动。
3. `services/catalog-sync.ts` / premium 的设置写入仍只在**内存**（`db/mod.ts`），
   不回写 Postgres；即便 main.ts 首启把 `data.json` 的设置 seed 进了 PG，运行期的改动不持久。
   `startCatalogSync()` 也未被调用 —— 目录/p 许可证同步实际是"半接线"。
4. `db/data.json`、`dist/` 仍在 `.gitignore`：干净 clone 复现不了线上内容。

**可复用规则**：**DDL 的"看起来对"要用真实数据库证伪，不能靠读代码**。
本次 8 个类型错误是静态可见的，但"缺表 + SQLite 语法 + 双主键"这三个致命问题，
只有把 `initDb()` 对着真 Postgres 跑一次才会现形 —— 而这恰好是线上 500 的真正原因。
